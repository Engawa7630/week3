## 练习4：Stack Overflow 问答对比

### 高票问题
**问题链接**：https://stackoverflow.com/questions/11227809/why-is-processing-a-sorted-array-faster-than-processing-an-unsorted-array  
**主题**：为什么处理排序数组比未排序数组更快？

**问题特点**：
- **清晰的标题**：直接点出问题和上下文
- **可复现的示例**：提供了完整的 C++ 代码，其他人可以直接运行验证
- **明确的预期**：想要理解性能差异的原因
- **诚实的尝试**：提问者表示自己已经尝试过搜索但仍然困惑

**为什么获得高票（>15000 分）**？
1. 问题本身非常有趣，触及了分支预测的核心概念
2. 提供了可运行的最小复现示例
3. 答案解释了底层原理，不满足于"因为缓存"这种表面回答
4. 无论新手还是专家都能从中受益

### 被关闭/点踩的问题

**问题链接**：https://stackoverflow.com/questions/12345678/（假设示例）  
**主题**：Python 代码报错，怎么办？

**问题内容**（假设）：
> "我的 Python 代码报错了，谁能帮我看看？"

**问题缺点**：
- **缺少上下文**：没有说明使用的 Python 版本、操作系统
- **缺少复现步骤**：没有提供完整的代码或错误信息
- **问题不具体**："报错"是一个极其模糊的描述
- **缺少努力证明**：没有说明提问者已经尝试过什么

**为什么被关闭/点踩**？
1. 问题无法被回答（信息不足）
2. 不符合 Stack Overflow 的"可复现"要求
3. 更像是"为我写代码"而不是"帮我理解问题"

---

### 结论

能否预见哪个问题更可能得到好答案？

**可以预见**。高票问题的特点非常明显：
- 提问者付出了努力（提供了示例、描述了自己的尝试）
- 问题本身有教育价值（涉及普遍原理而非一次性场景）
- 问题可以通过具体、可验证的方式回答

低质量问题的共同特征是：
- 提问者希望别人替他做工作
- 问题模糊，回答者需要猜测上下文
- 即使给出了答案，也很难对其他人有帮助
